# Кошель

Настольный учёт финансов для Windows: привычный мобильный трекер расходов,
скрещённый с рабочим пространством Obsidian и движком прогноза.

## Запуск

Обычный способ — двойной клик по **`Кошель.bat`** в папке проекта. При первом
запуске он сам поставит зависимости и соберёт интерфейс, дальше будет открывать
окно сразу. Ярлык можно закрепить: правый клик по файлу → «Показать
дополнительные параметры» → «Отправить» → «Рабочий стол (создать ярлык)».

Из терминала то же самое делается так:

```bash
npm install
npm start
```

Для разработки с горячей перезагрузкой — `npm run dev` (вместе поднимаются
Vite и Electron).

Файл `index.html` открывать напрямую бесполезно: это точка входа для сборщика,
а не готовая страница.

Чтобы поставить программу как обычное приложение — с ярлыком, записью в
«Установку и удаление программ» и связью файлов `.kashel` — соберите установщик:

```bash
npm run dist
```

Он появится в `release/` под именем «Кошель 1.0.0 установщик.exe». Установщик
спрашивает папку, ставит только для текущего пользователя (права администратора
не нужны) и сам связывает `.kashel` с программой.

Дополнительно:

- `npm run icon` — пересобрать иконку программы (нужно, только если менялся рисунок);
- `npm run selftest` — проверка расчётных движков на сгенерированных данных;
- `npm run uitest` — прогон интерфейса в jsdom: разделы, оформления, массовое удаление;
- `npm run typecheck` — проверка типов;
- `npm run build` — только сборка интерфейса в `dist/`;
- `npm run keygen` — ключи и адрес для обновлений (см. ниже);
- `npm run release` — собрать и подписать выпуск для выкладки;
- `npm run site` — собрать страницу скачивания вместе с браузерной версией.

Если после `npm install` появляется ошибка «Electron failed to install correctly»,
бинарник не распаковался (обычно из-за антивируса или прав на запись). Лечится так:

```bash
npm rebuild electron
```

## Обновление у тех, кому вы раздали программу

Установщик отдаётся человѣку один раз, дальше он берёт новые версии сам:
в «Настройках» есть кнопка «Проверить обновление», и раз в сутки программа
смотрит сама — молча, ничего не скачивая без согласия.

Работает это так. На вашем хостинге рядом с установщиками лежит объявление
`update.json`: версия, что нового, ссылки и контрольные суммы. Программа его
читает и сравнивает со своей версией.

Объявление подписано. Обновлятель по своей природе скачивает чужой файл и
запускает его правами человѣка — это ровно тот механизм, который нужен
злоумышленнику, и одной контрольной суммы мало: она лежит в том же объявлении
на том же хостинге, и взломавший хостинг перепишет оба. Поэтому объявление
подписывается ключом, который есть только у вас, а в программу зашит открытый.
Подменённое объявление не проходит проверку, и ничего не скачивается.

### Где всё это лежит

Бесплатно и без своего сервера получается так:

| Что | Где | Почему там |
|---|---|---|
| Установщики | GitHub Releases | Предел 2 ГиБ на файл, трафик не считают |
| Страница скачивания и веб-версия | GitHub Pages | Бесплатно, собирается само при отправке кода |
| Объявление об обновлении | GitHub Releases, рядом с установщиками | Программа берёт его оттуда же, откуда файлы |

Почему не Cloudflare Pages, Netlify и Vercel: у них потолок около 25 МиБ на
файл, а установщики весят 82 и 110 МБ. Двоичным файлам место в Releases.

Оговорка про Россию: доступ к GitHub из РФ технически ограничен, а Netlify
заблокирован и вовсе. Тем, кто без VPN, ссылки могут не открыться — если это
станет мешать, установщики придётся переложить на российский хостинг, и тогда
меняется только адрес в `electron/updatekey.js`, остальное работает как есть.

### Один раз: завести ключи и указать адрес

```bash
npm run keygen -- https://ваш-сайт/обновления
```

Закрытый ключ ляжет в `~/.kashel-release-key.pem` — **вне проекта, никому не
показывать и не терять**: потеряете, и выпускать обновления для уже разданных
копий будет нечем. Открытый ключ и адрес запишутся в `electron/updatekey.js` и
уедут внутрь программы.

Повторный запуск ключи не перезаписывает — только адрес. Это нарочно: новая
пара ключей сделала бы уже разданные копии неспособными принять обновление.

### Каждый раз: выпустить версию

1. Поднять номер версии в `package.json`.
2. Собрать: `npm run dist` и `npm run dist:appimage`.
3. Сложить выпуск: `npm run release -- "Что нового в этой версии"`.
4. Выложить всё содержимое `release/upload/` по адресу, который вы задали
   при `keygen`.

В `release/upload/` окажутся установщики, `update.json` и `update.json.sig`.
Скрипт выпуска сам проверяет свою подпись перед тем, как объявить готовность:
подписать и не суметь проверить — обычная беда, и обнаружиться она должна у
вас, а не у приятеля.

Проверить, что выложилось верно, можно браузером: `…/update.json` должен
открываться и показывать номер версии.

### Сайт: страница скачивания и веб-версия

`site/index.html` — страница скачивания, `npm run site` складывает её вместе с
браузерной версией программы в `_site/`:

```bash
npm run site -- имя/репозиторій
```

Получается `_site/index.html` (страница) и `_site/app/` (сама программа для
браузера). Тем же скриптом пользуется рабочий процесс `.github/workflows/pages.yml`,
который публикует всё это на GitHub Pages при каждой отправке в `master`.
Скрипт один нарочно: повтори сборку в yml построчно, и две копии разошлись бы
при первой правке, а обнаружилось бы это уже на живом сайте.

Версию и прямые ссылки страница спрашивает у GitHub через `api.github.com`.
Напрашивалось брать их из `update.json`, но так нельзя: вложения выпусков
отдаются браузеру без заголовка `Access-Control-Allow-Origin`. Проверено
вживую — запрос к `releases/latest/download` падает с ошибкой CORS, к API
проходит.

Про браузерную версию стоит понимать, что она не замена программе. Данные в
ней лежат внутри браузера: между устройствами не ходят, а очистка истории
сайта их стирает. Это проба, а не рабочее место.

## Хранилище

Все данные лежат в одной папке обычными текстовыми файлами — их можно читать
глазами, версионировать через git и синхронизировать любым облаком.
По умолчанию это `Документы\Кошель`, сменить папку можно в настройках.

```
Кошель/
  data.json                 счета, категории, цели, сценарии, регулярные платежи, настройки
  transactions/2026-08.json операции, разложенные по месяцам
  notes/*.md                заметки в markdown
  canvas/*.canvas           канвасы (формат JSON Canvas, совместим с Obsidian)
  attachments/              фото чеков
```

Новое хранилище открывается почти пустым: программа не придумывает за вас ни
счетов, ни операций — на дашборде появится приглашение создать первый счёт.
Единственное исключение — категории: при первом запуске кладётся стандартный
набор, двадцать одна расходная и семь доходных, с иконками и цветами. Без них не
работают ни плитки быстрого ввода, ни отчёты, а набор у всех примерно
одинаковый; лишнее удаляется в «Категориях», как обычные категории. Кнопка
«Стереть всё» возвращает то же состояние — как у только что установленной
программы. Генератор демо-данных остался только в тестовой оснастке
(`scripts/fixture.ts`), чтобы было на чём прогонять прогноз и советы.

Сохранение трёхуровневое: изменения пишутся на диск через доли секунды после
правки, раз в пять минут хранилище переписывается целиком на случай сбоя,
и закрытие окна сбрасывает несохранённое. Кнопка в правом углу строки
состояния показывает время последней записи и сохраняет по требованию —
то же делает `Ctrl+S`.

Регулярные платежи проводятся один раз за месяц: у правила запоминается
последний проведённый месяц, поэтому удалённое автосписание не появляется
снова при перезапуске.

### Всё одним файлом

Хранилище целиком сворачивается в один файл `.kashel` — меню «Файл» →
«Сохранить как…» (Ctrl+Shift+S) или та же кнопка в «Настройках». Внутри
операции, счета, категории, цели, регулярные платежи, сценарии, правила импорта,
заметки, канвасы и фото чеков. Файл можно унести на другой компьютер или
отправить человеку.

Открывается он тремя способами: двойным кликом по самому файлу, через «Файл» →
«Открыть…» (Ctrl+O) и кнопкой в «Настройках». Связь `.kashel` с программой
ставит установщик; если Кошель запускают прямо из папки проекта, её включает
кнопка «Связать файлы .kashel с Кошелем» в настройках — она пишет две записи
в вашу ветку реестра и прав администратора не требует.

Программа работает в одном экземпляре: двойной клик по файлу при уже открытом
окне передаёт файл ему, а не поднимает вторую копию поверх того же хранилища.

Внутри обычный JSON с отступами — открывается блокнотом, кладётся в git,
чинится руками. Фото чеков лежат в нём в base64, поэтому с ними файл заметно
тяжелее; всё остальное — текст.

```
{
  "kashel": "vault",          признак архива, без него файл не примут
  "formatVersion": 1,
  "exportedAt": "…",
  "counts": { … },            что внутри — показывается перед загрузкой
  "data": { … },              то же, что в data.json, плюс операции
  "notes": { "Имя": "текст" },
  "canvases": { "Имя": { … } },
  "attachments": { "attachments/…": "base64" }
}
```

Загрузка заменяет хранилище целиком, поэтому перед заменой программа сама
складывает нынешнее состояние таким же архивом в `backups/` — вернуться можно
той же кнопкой. Настройки внешнего вида и финансовый профиль в файл кладутся,
но при загрузке не применяются: чужая тема и чужой день зарплаты получателю
не нужны. Файл приходит извне, поэтому всё, что из него читается, проверяется:
записи без даты, узлы без идентификатора и вложения с путём за пределы
хранилища отбрасываются, а их число показывается перед загрузкой.

## Что внутри

**Учёт.** Дашборд с бубликом по категориям и переключателем периода
(день / неделя / месяц / год / произвольный), счета пяти типов — карты, наличные,
копилки, кредиты и долги людям, — категории с иконками, цветами и месячными
лимитами, разбиение одного чека на несколько категорий, теги, комментарии,
фото чеков, регулярные платежи с автосозданием операций.

**Массовые операции.** На дашборде под бубликом есть карточка «Очистка» с тремя
кнопками. Две верхние — удалить все расходы и удалить весь заработок — подчиняются
выбранным сверху периоду и счёту, показывают в себе количество затронутых записей
и не задевают переводы между счетами. Нижняя, «Стереть всё и начать заново»,
период игнорирует: она возвращает хранилище к состоянию только что установленной
программы, удаляя операции, счета, категории, цели, регулярные платежи, заметки
и канвасы. Настройки при этом сохраняются. Отмены у неё нет — только предварительный
экспорт. Та же кнопка есть в настройках.

В разделе «Операции» список выделяется целиком одной кнопкой, а день — одним
щелчком по его заголовку; выделение подчиняется текущему фильтру, так что можно
снести только одну категорию или один счёт.

Перед любым групповым удалением показывается, что именно уйдёт — сколько
записей, на какие суммы и за какой промежуток, — а после появляется кнопка
«Вернуть», восстанавливающая удалённый пакет до закрытия программы.

**Иконки.** Категории, счета и цели помечаются контурными иконками — 369 штук
на 441 месте в пятнадцати разделах: финансы, еда и напитки, транспорт, покупки,
дом, здоровье, красота, развлечения, счета и услуги, спорт, отдых, образование,
семья и дети, работа и доход, прочее. Одна и та же иконка может стоять в
нескольких разделах — ванна нужна и в доме, и в красоте.
Каталог открывается кружком в карточке; там же поиск по русским названиям
(«кофе», «такси», «зал») и палитра, потому что иконка и цвет — одно решение.
Иконка рисуется той же линией, что и остальной интерфейс, и красится
`currentColor`, поэтому подстраивается под тему сама; цвет кружка сплошной, а
линия внутри выбирается по его светлоте — белая на тёмном, почти чёрная на
светлом, чтобы жёлтая категория не превращалась в белое пятно.

Иконки взяты из набора [Lucide](https://lucide.dev) (лицензия ISC) и вшиты
путями прямо в исходник (`src/lib/catalog.ts`) — без пакетов и сетевых
запросов. Старые записи, где в поле иконки лежит эмодзи, продолжают
показывать эмодзи, пока их не сменят вручную.

**Оформление.** Шесть тем, различающихся не только цветом, но и характером —
скруглениями, плотностью, тенями, толщиной границ: «Обсидиан» (спокойная тёмная),
«Графит» (строгая и плотная), «Стекло» (полупрозрачные панели с размытием),
«Неон» (контраст и свечение), «Мята» (светлая зелёная) и «Тёплая бумага».
Выбираются в галерее — кнопка в ленте слева или раздел настроек, применяются
мгновенно. Рядом переключатель анимаций: как в системе, выключены, умеренные, полные.
Системная просьба уменьшить движение (в Windows — выключенные «Эффекты анимации»)
задаёт поведение только в режиме «как в системе»; явный выбор её перебивает,
и об этом честно написано прямо в галерее.

Оживлены: денежные суммы перекатываются цифрами при изменении
([number-flow](https://github.com/barvian/number-flow)), списки операций и
категорий плавно перестраиваются при добавлении и удалении
([auto-animate](https://github.com/formkit/auto-animate)), окна и переходы между
разделами идут на пружинах ([motion](https://github.com/motiondivision/motion)),
уведомления складываются стопкой и умеют кнопку действия
([sonner](https://github.com/emilkowalski/sonner)) — например «Удалено 49 операций · Вернуть».

Декоративные эффекты сделаны по мотивам
[React Bits](https://github.com/DavidHDev/react-bits) (MIT + Commons Clause): блик по
названию программы, переливающийся заголовок пустого хранилища, световая полоса
на карточках счетов и категорий при наведении, каскадное появление советов и искры
при нажатии главных кнопок. Цвета переведены на переменные тем, а рисование искр
переписано так, чтобы цикл отрисовки спал, пока искр нет. Все эффекты включаются
только на уровне анимаций «полные» — «умеренные» оставляют лишь функциональное
движение.

**Быстрый ввод.** `Ctrl+N` и строка вида `кофе 250 кафе вчера #работа @наличные` —
сумма, категория, дата, теги и счёт разбираются из текста. Числа расставляются
по разрядам прямо в поле, а под строкой — плитки категорий с иконками:
сначала закреплённые, дальше просто частые за последние три месяца. Кнопка
«Ещё» разворачивает весь список и включает на плитках кружок, которым категория
закрепляется в частых или убирается оттуда. Нажатая плитка главнее того, что
удалось угадать из текста, и видна в подсказке под строкой.

**Прогноз.** По каждой категории считается устойчивый уровень (винзоризованное
среднее), сезонность по месяцам года и тренд по десезонализированному ряду;
регулярные платежи подставляются точными суммами. Поверх — Монте-Карло на
фактическом разбросе ваших месяцев, дающий коридор от 10-го до 90-го процентиля.
Режим «что если» — ползунки по категориям и доходу, разовые события,
сохраняемые сценарии.

**Аналитика.** Три разных взгляда на одни и те же операции.

*Сравнение с прошлым периодом.* Рядом с доходом, расходом и итогом на дашборде
стоит изменение к такому же прошлому периоду, и то же самое — у каждой строки
в списке категорий. Незаконченный период сравнивается не с целым прошлым,
а с таким же его куском: пятого числа месяц не может быть «дешевле»
предыдущего просто потому, что ещё не прожит. В подсказке видно, сколько было
и за какой отрезок. Рост расхода подсвечен как плохая новость, рост дохода —
как хорошая.

*Календарь.* Год днями: колонка — неделя, строка — день недели, насыщенность
клетки — сколько в этот день потрачено или получено. Уровни заливки берутся
от квантилей, а не от максимума, иначе одна крупная покупка делает весь
остальной год одинаково бледным. Клик по дню разворачивает его операции, из
них можно уйти в «Операции» с уже сжатым до этого дня периодом. Рядом —
сколько всего, сколько в среднем в день, самый дорогой день и сколько дней
прожито без трат.

*Итоги года.* Заработано, потрачено, отложено и норма сбережений — каждое
со сравнением с прошлым годом «по то же число». Дальше: помесячный график,
рекорды года (самый дорогой день, крупнейшая трата, самый дорогой и самый
экономный месяцы), раскладка по категориям с изменением к прошлому году,
средний чек, расход в день, дни без трат и теги года.

**Советы.** Три десятка локальных правил без обращений в сеть: забытые подписки,
категории выше собственной нормы, эффект мелких частых трат, превышение лимитов,
норма сбережений, подушка безопасности, раскладка 50/30/20, концентрация и
волатильность дохода, отставание дохода от инфляции, простаивающие деньги,
порядок погашения кредитов, достижимость целей, запас до зарплаты. У каждого
совета — расчёт эффекта в рублях в месяц и кнопка, собирающая из него сценарий
прогноза.

Восемь правил разбирают не суммы, а структуру и ритм трат:

- *серия дней подряд с тратами* — привычка тратить каждый день не видна ни в
  одной сумме, но именно она съедает случайную экономию;
- *сезонный пик впереди* — сезонность из движка прогноза превращается в
  предупреждение заранее: «сентябрь у вас обычно дороже на столько-то,
  отложите заранее»;
- *крупная трата год назад в этом же месяце* — страховка, шины, продление
  домена: раз в год, поэтому не попадает ни в регулярные платежи, ни в норму;
- *цена против объёма* — рост категории раскладывается точно на две причины:
  подорожала покупка или покупок стало больше. Управляемо обычно только второе;
- *категория-новичок в топе* — появилась месяц-другой назад и уже в пятёрке;
- *затухшая категория* — три месяца тишины там, где раньше были деньги:
  либо пора архивировать, либо траты перестали попадать в учёт;
- *лидер по числу операций, а не по деньгам* — куда уходит внимание, а не бюджет;
- *подозрение на дубль* — совпали день, сумма, категория и комментарий:
  двойное списание банка, повторный импорт или дважды занесённая операция.

**Канвас.** Бесконечная доска с карточками и стрелками. Карточкой может быть
свободный текст с markdown, заметка из хранилища (показывает своё содержимое),
живой счёт, категория или цель с настоящими цифрами, сценарий прогноза или
блок-запрос с графиком. Стрелка между счётом и категорией показывает оборот
между ними — толщиной линии.

Карточки: размер меняется за любой из четырёх углов, рамка всегда окрашена
в цвет карточки — выделенная светится ярче. В меню цвета семь кружков быстрого
доступа и вход в полную палитру из шестнадцати цветов, где булавкой можно
собрать свой быстрый ряд; набор хранится в файле доски, у каждой схемы свой.

Текст карточки — markdown с панелью форматирования: заголовки, жирный, курсив,
подчёркивание, зачёркивание, маркер, код, списки, задачи, цитаты и `[[ссылки]]`.
Есть кегль и четыре режима поведения текста: обычный с прокруткой, тянуться
за карточкой, вписываться уменьшением шрифта и растить карточку под содержимое.
`Ctrl+B`, `Ctrl+I` и `Ctrl+U` работают прямо при вводе.

Редактор: перетаскивание за кружок на краю тянет связь, и если отпустить её на
пустом месте, программа спросит, что там создать, — новая карточка сразу окажется
подключённой. Клик по связи выделяет её и открывает панель с подписью, цветом и
направлением стрелки; концы можно перецепить на другие карточки. Есть рамочное
выделение, перемещение группой с направляющими и привязкой, копирование через
`Ctrl+C`/`Ctrl+V`, отмена и повтор через `Ctrl+Z`/`Ctrl+Y`, контекстное меню по
правому клику на карточке, связи и полотне. Оформление карточек переключается
между тремя вариантами: «Полные», «Как в Obsidian» и «Плашки».

Полотно двигается средней кнопкой, пробелом или `Alt`, масштабируется колесом.

**Заметки и граф.** Markdown с `[[вики-ссылками]]`, обратными ссылками и тегами.
Граф связей заметок, категорий, счетов и целей.

**Живые запросы.** Блок в заметке или на канвасе, который сам считает по операциям:

````
```kashel
type: chart
chart: donut
kind: expense
period: 6m
group: category
limit: 8
```
````

Ключи: `type` (sum / table / chart / list), `chart` (donut / line / bar),
`kind` (expense / income / transfer), `period` (`6m`, `30d`, `month`, `year`,
`2026-07`, `2026-01..2026-06`, `all`), `group` (category / month / tag / account),
`category`, `tag`, `account`, `limit`.

**Импорт.** Любой CSV с ручным сопоставлением колонок, автоопределением
разделителя и кодировки windows-1251, правилами автокатегоризации и отловом
повторов по дате, сумме и описанию.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl+P` | палитра команд |
| `Ctrl+N` | быстрый ввод операции |
| `Ctrl+Shift+F` | поиск по операциям и заметкам |
| `Ctrl+W` | закрыть вкладку |
| `Ctrl+\` | разделить панель |
| `Ctrl+B` / `Ctrl+I` | левая и правая панели |
| `Ctrl+S` | сохранить хранилище немедленно |
| `Delete` | удалить узел на канвасе |

## Устройство кода

```
electron/     главный процесс и мост к файловой системе
src/lib/      типы, форматирование, даты, иконки, markdown
src/engine/   статистика, прогноз, советы, запросы, разбор ввода, CSV
src/state/    хранилище, автосохранение, демо-данные, кэш аналитики
src/components/ графики (свои SVG, без библиотек) и общие элементы
src/views/    пятнадцать разделов приложения
```

Денежные суммы везде хранятся целыми копейками — никаких накоплений
ошибки округления в итогах.
